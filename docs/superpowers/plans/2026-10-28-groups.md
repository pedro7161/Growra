# Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let players create their own Groups (Schedule or List) beside Personal and Work, add one item to several linked groups, show groups on the dashboard and calendar, and share any group (or Personal/Work) by code, with no rewards for group items.

**Architecture:** Groups live in a new `GameState.groups` array; each group holds its own `tasks` (List) or `workItems` (Schedule), so the game logic that reads `gameState.tasks` / `gameState.workItems` never sees them. Pure functions in `src/utils/groups.ts`, `groupLinks.ts` and `groupCode.ts` do all the state changes. The existing Work and Tasks screens are generalised to take their items and handlers from a "holder" (`"personal" | "work" | groupId`), so no screen is copied.

**Tech Stack:** Expo 54 / React Native 0.81, TypeScript, Jest (ts-jest, jsdom, TZ=Europe/Lisbon).

**Spec:** `docs/superpowers/specs/2026-10-28-groups-design.md`. Sections 8–11 override earlier text. The UI name is "Groups" / "Grupos". Code uses `Group` / `groups` / `groupId` and never `category` (that word is the existing task tag).

## Global Constraints

- All user-visible text goes in `src/constants/appCopy.ts`, in both `en` and `pt` (pt-PT); `__tests__/translations.test.ts` keeps passing.
- No network, accounts or servers.
- Layout must work at 360 px wide and use the existing themes via `getAppTheme`.
- `SAVE_VERSION` goes from 21 to 22, purely additive; older builds refuse v22 through the existing check. Existing tasks, work items, coins, streak, companions, rooms and settings are unchanged by the migration.
- Group items never change `coins`, `totalExperience`, `level`, `streak`, `usage`, `days`, `pets`, `companionEvents`, `totalTasksCompleted` or `decorations`, and never show the praise bubble.
- At most 10 groups (`MAX_GROUPS = 10`).
- Branch `feature/groups` (already checked out). Commit after each task. Run `npx tsc --noEmit`, `npx jest` and `npm run lint` before each commit. Never push or merge.

## Review Focus

- **Repeating list tasks inside a group:** a daily group task ticked today must come back as pending tomorrow, the same as Personal tasks via `syncRecurringTasks`.
- **Ticking in a group is reward-free:** coins, XP, streak, usage, days and Bond are identical before and after, from every place a group item can be ticked (group screen, dashboard row).
- **Linked "This and all following" across copies with different exceptions:** each copy keeps its own earlier one-day exceptions; only the chosen copies change.
- **Bad codes:** truncated, edited (checksum), newer-version or wrong-prefix codes return an error and leave the state untouched. Importing at the 10-group cap is refused with a message.
- **Deleting the remembered group:** if `settings.tasksSection` or `settings.calendarShow` refers to a deleted group, Tasks falls back to the chooser and the calendar drops it, with no crash.

A "following" split gives the continued item the same new `linkId` in every chosen holder.

### Task 3: Sharing by code

**Files:**
- Create: `src/utils/groupCode.ts`
- Test: `__tests__/groupCode.test.ts`

**Interfaces:**
- Consumes: Task 1 (`createGroup`, `MAX_GROUPS`, holder accessors). Mirror the `roomCode.ts` format helpers (base64url and checksum), extracting them to a shared util if that is clean.
- Produces:
  - `GROUP_CODE_VERSION = 1` and the prefix `"GROWRA-GROUP-"`.
  - `buildGroupShare(state, holder, sourceId: string): GroupShare`, where `GroupShare = { sourceId: string; name: string; color: string; kind: GroupKind; tasks: Task[]; workItems: WorkItem[] }`. It strips `linkId`, completions, timer state and ids. For "personal" / "work", `name` is the localised built-in name and `sourceId` comes from a stable per-player id (`state.playerId + ":" + holder`); for a group it is `group.sourceId ?? group.id`.
  - `encodeGroupCode(share): string`.
  - `decodeGroupCode(text): { share: GroupShare } | { error: "format" | "checksum" | "newer" }`.
  - `shareSummary(share): { count: number; kind: GroupKind }`.
  - `importGroupCode(state, share, now, newId, mode: "new" | "update"): GameState | { error: "cap" }`. With "update", it replaces the items of the existing group with the same `sourceId` and keeps that group's name, colour and settings. With "new", it creates a group with `sourceId` set, fresh ids and nothing ticked.
  - `findImportedGroup(state, sourceId): Group | undefined`.
